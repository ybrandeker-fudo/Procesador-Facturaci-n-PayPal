📏 Reglas del proceso 13 reglas vigentes · click para desplegar
1 Clasificación de pagos
Cada cobro del extracto PayPal se cruza con el historial Dash y se clasifica según el campo Acción y Dias cobrados del plan viejo:
  • Pago regular → Acción = "Pago regular" + días viejo = 0.
  • Upgrade → Acción = "Cambio de plan". El cliente agregó un módulo o subió de plan.
  • Migración de plan → Acción = "Pago regular" + días viejo > 0. Se factura plan viejo + plan nuevo prorrateados.
2 Descuentos por frecuencia
Descuentos automáticos cuando no hay promo específica aplicada:
  • Mensual → 0%
  • Suscripción → 5%
  • Semestral → 10%
  • Anual → 15%
Si hay código de promoción cargado en la Tabla de promociones, se usa el descuento específico de esa fila (puede variar por componente).
3 Upgrades · Unificación Plan + Módulo
Cuando en el mismo cobro el cliente hizo upgrade de Plan y Módulo simultáneamente, el término se unifica en una sola etiqueta Upgrade Plan y Módulo - <Frecuencia> aplicada a todas las líneas. Odoo requiere un único valor por factura.
Solo Plan → Upgrade Plan - Mensual
Solo Módulo → Upgrade Módulo - Mensual
Plan + Módulo → Upgrade Plan y Módulo - Mensual
4 Migraciones · Descomposición de líneas
Una migración factura cada componente por sus días correspondientes:
  • Plan viejo → días del plan viejo (cobro proporcional).
  • Plan nuevo → días del plan nuevo.
  • Módulo compartido (en ambos planes) → suma de días viejo + nuevo.
  • Módulo solo viejo o solo nuevo → días que corresponden.
5 Suscripción implícita
Si el ratio importe cobrado / bruto cae en [0.93, 0.97] (≈ 5% de descuento), el comportamiento varía por tipo de cobro:
  • Upgrades: se aplica Suscripción automáticamente (el historial trae mal Suscripción=No por bug conocido).
  • Regulares y Migraciones: NO se aplica automático. Si Suscripción=No y el importe cierra con 5%, se marca [REVISAR] + aviso para que el humano decida.
6 Cuentas de Uruguay (-uy → -int)
Los productos con sufijo -uy (cuentas de Uruguay) se mapean automáticamente al equivalente -int en el catálogo, porque los productos de Odoo están definidos solo con -int. Internamente el script busca pro-uy como pro-int, por ejemplo.
7 Códigos de promoción múltiples
El campo Nombre de la promociones del historial puede traer varios códigos separados por coma. El lookup funciona en 2 pasos:
  1. Primero prueba el string completo en la Tabla (ej. "PROMO_X, PROMO_Y" como una entrada).
  2. Si no matchea, lo divide por comas y busca cada código individual. Elige el que da mayor descuento para ese componente.
8 Términos y condiciones (regulares)
Formato automático según el período cubierto:
  • Período en un solo mes → Septiembre 2026
  • Período Semestral → Junio 2026 - Noviembre 2026
  • Período Anual → Junio 2026 - Mayo 2027
9 Nota interna
Formato: <PromoIndividual>/<ID Dash>/<Tipo>/<Letra frecuencia>. Letras: M=Mensual · R=Suscripción · T=Trimestral · S=Semestral · A=Anual. Para upgrades sin promo: SP/<ID>/B/<letra>.
10 Validaciones de control del historial
El procesador corre 10 checks sobre el historial para detectar inconsistencias. No bloquean la facturación pero quedan en la hoja Avisos de control del XLSX:
  • Importe extracto ≠ Importe historial
  • Ratio importe/completo inconsistente con la frecuencia
  • Estado del pago ≠ "Aprobado"
  • Duplicados: misma ref PayPal 2+ veces
  • Fechas inconsistentes (inicio > fin)
  • Frecuencia no reconocida
  • Días negativos o > 400
  • Suscripción="Sí" con Frecuencia Trim/Sem/Anual
  • Migración con Plan viejo vacío
  • Componente desconocido no cargado en catálogo
11 Faltantes para Tabla
Cuando aparece un código alfanumérico que no está en la Tabla de promociones, se agrega a la hoja Faltantes para Tabla del XLSX con: código, componente, frecuencia(s), veces que apareció y cliente ejemplo. Está ya en formato copy-paste para agregarlo al Drive compartido.
12 Planes activos y obsoletos
  • Planes activos para upgrades: solo adv y pro.
  • Planes obsoletos: ba, st, fu, ini. Si aparecen como plan viejo o nuevo en un upgrade/migración → se marca [REVISAR] para análisis manual.
  • Módulos válidos: dv, tbl, idvsls, top, kds, aih.
  • Downgrades se ignoran si hay también upgrade. Si TODO es downgrade → [REVISAR].
13 Constantes del output Odoo
Valores fijos aplicados a todas las líneas del XLSX:
  • Diario: Comprobantes de exportación
  • Tipo de Documento: FACTURAS DE EXPORTACIÓN
  • Moneda: USD
  • Cuenta analítica: {"6": 100} (Inbound Otros Países, imputación 100%)
  • Impuesto: IVA Exento
  • Unidad de medida: Unidades
